# 问题分析回执 — Open3D 预览位姿偏移与朝向异常（2026-09-07）

> 对应《现有问题.md》。结论先行：**推断 1 命中根因**（抓取参考系映射假设错误），
> 推断 2/4 是它的伴生现象，推断 3（闭合态 vs 预塑形）是真实的二阶误差源但非本次
> 主因。已修复并回归验证，无需上真机排查。

## 一、根因确认（对应推断 1）✅

旧锚定把两指抓取的**接近轴（grasp X）直接绑在自研手手指延伸轴（base +X）**上。
但核对上游资产生成源码 `scripts/legacy/angles2stl.py:275-306
common_grasp_information` 发现，Inspire 查表的抓取系定义是：

```
point0 = 拇指接触质心;  point1/point2 = 食指两个部位的接触质心
C      = (point0 + (point1+point2)/2) / 2        ← 抓取中心（锚点）
tool_x = normalize(normal(point0, point1, point2)) ← 接近轴 = 接触三角形法向
tool_y = normalize(point0 − C)                     ← 开合轴 = 拇指方向
```

即**接近轴 = 拇指/食指接触点构成三角形的法向（包络"杯口"朝向）**，不是手指延伸轴。
两只手都是斜向包拢：手指方向与接近轴成 ~50°（真实 JSON 实测 Inspire 掌心 X 与抓取
X 夹角 49.4°）。v1 把手指轴硬对齐接近轴，等于命令手"指尖竖直插桌、掌心朝侧"——
与截图现象完全一致。

**这也解释了为什么 v1 的闭合测试全部通过**：那些判据校验的是"锚定点=抓取点"的
构造一致性，校验不出"构造假设本身错了"。

## 三、修复内容（已完成）

1. **`own_hand_grasp.py` 重写锚定构造**：按上游公式移植——接近轴=接触三角形法向、
   开合轴=拇指方向、锚点=中点公式；法向符号自动定向（掌体 base_link 在杯口负侧）。
2. **接触组数值锁定**（`scripts/tools/search_contact_groups.py`）：逐类型枚举指节
   组合，选与 Inspire 查表约定面外倾斜最小的组合。结果：Type 1/2/3/5/6 =
   食指两指节（index_1+index_2，上游"食指两个三角面"的忠实移植）、Type 4 =
   index_2+middle_2、Type 7 = ring_1+little_2、Type 8 = index_1+middle_2。
   面外倾斜从 20-63° 降到 **16-35°**（`check_grasp_frame_convention.py` 可复验），
   残余部分是两手形状差异，不可再约。
3. **`hand_mount_z_own` 语义修正**：0.0775→**0.05**。认识更正：它是法兰→手 base
   的**物理安装距离（常数）**，不应逐类型拟合旧链路（旧链路对自研手本来就是错的）；
   类型 2/3/4 独立收敛于 49-52mm 印证支架长约 5cm。建议真机尺量核实。
4. **own 模式关闭朝向闸门**（`orient_deviation_thresh_deg_own=180`）：新构造下法兰
   X=手指方向+逐类型拇指方位，与固定朝向的全姿态偏差常超 90°（滚转为主），旧闸门
   会错误回退固定朝向、破坏锚定。不可达朝向的兜底由执行器 IK 级固定朝向候选承担。
5. **回归结果**：selftest 三类型判据 0 误差；B4 闭合测试三判据 0 误差；
   selftest 渲染图（docs/hand_renders/own_anchor_selftest_t{3,5}.png）手呈斜向
   包拢、包络套住目标，不再是"指尖插桌"。
