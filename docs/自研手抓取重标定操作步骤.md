# 自研手抓取重标定操作步骤（新手版 · 零手工测量）

**目标**：把现有管线（Inspire 手几何规划 + offset 补偿）适配自研手的真实几何，提升抓取精度。

**核心思路**：不用卡尺、不用拍照量尺寸——
- **几何量**（开口宽度、掌长、包络中心、闭合端点角）全部由自研手 URDF 名义 CAD **计算**得出，这是 URDF 精度最高的用法，优于任何手工测量；
- **安装误差**（装歪、掌长差）不单独测，由阶段 4-5 的 jog 标定闭环**实测整链系统误差并吸收**——闭环穿过整个真实系统，本来就是真值来源；
- **电机↔关节角**用 URDF 力学端点 + 线性假设建初版映射，中段残差由闭环与包络抓的容差兜底。

**总耗时**：约 1-2 个工作日。

**先做哪个手型**：只练 2 种——**Type 3（Prismatic 3-Finger 四指捏）** 和 **Type 5（Medium Wrap 包络抓）**，其余类型以后照搬同样流程。

## 自研手几何模式（2026-09-07 起默认，hand_model=own）

抓取位姿锚定已从 Inspire 查表换为自研手 URDF 几何（`own_hand/own_hand_grasp.py`），config `grasp_config.json` 的 `"hand_model": "own"` 已生效。命令变化：

```bash
# 预览（终端B）——命令不变，自动走 own 锚定；渲染的自研手 mesh 应包住目标物体
python run_inspire_preview.py --visualize --collision --preprocess \
    --min_depth 0.2 --max_depth 0.6 --fixed-type 3

# A/B 对比时切回旧 Inspire 锚定：加 --hand-model inspire
```

要点：
- `--fixed-type 3` 固定抓取类型（A/B 实验排除选型干扰，1-8 可选）；
- own 模式 JSON 顶层位姿语义 = 自研手 base 帧；执行器无需任何改动；
- own 安装参数初值：`hand_mount_z_own=0.0775`、`mount_yaw_deg_own=0`（config 可调）；
- jog 标定历史请写独立文件：`anydex_eih_grasp_calib.py --calib-jog --jog-history ../logs/jog_calib_history_own.jsonl`，与 inspire 时代数据分开分析；
- 预览渲染检查（每轮必看）：**自研手 mesh 的包络空腔套住物体、拇指在两指抓取框的开合轴一侧**；法兰框（绿/橙）位置应与旧模式同数量级（差 2-3cm 属预期，来自掌心↔base 的几何差）。
- 详见 `docs/自研手几何替换Inspire-进度与计划.md`（含坐标约定与已修 bug 记录）。

**前置说明**：阶段 1 的计算工具 `scripts/tools/compute_hand_geometry.py` **已就绪并验证通过**（pybullet 加载 URDF 做 FK + 远端指节-掌面距离分析），产物 `docs/自研手几何数据.md` 和 `docs/hand_renders/` 五档渲染图已生成，可直接开始。

## 阶段 1：URDF 计算自研手几何表（纯计算，约 30 分钟）

**目的**：一次算出后面所有环节需要的自研手几何数据，全程无手工测量。

**工具**：`scripts/tools/compute_hand_geometry.py`（待实现）。运行环境只需 pybullet + numpy，不需要机械臂和相机上电，笔记本上就能跑。

```bash
conda activate anydex
cd ~/Projects/AnyDexGrasp_ws
python scripts/tools/compute_hand_geometry.py --types 3 5
```

工具做的事与输出：

1. **闭合端点角**：pybullet 加载 `assets/own_urdf/dexterous_hand/urdf/dexterous_hand.urdf`，用碰撞检查找出每根手指"指节 mesh 触到掌面 mesh"时的关节角——这就是电机位置 0（全闭）对应的真实关节角，不需要量。电机位置 2000（全开）= 关节角 0（机械限位，与 URDF 一致）。
2. **电机→关节角线性映射表**：两端点间线性插值，输出 0/500/1000/1500/2000 五档。
3. **开口宽度表**：FK 计算各电机档位下指尖位置 → 食指-拇指距离、四指张开跨度等，按手型输出"电机档位 ↔ 开口宽度 (mm)"。
4. **掌长与包络中心**：Type 3 / Type 5 预塑形位姿下，取参与指指节接触段表面采样点求质心 = 包络中心；输出包络中心在手坐标系下的偏移、以及"法兰→包络中心"的建议 `hand_mount_z` 初值。
5. 全部结果写入 `docs/自研手几何数据.md`（自动生成），作为后续唯一几何依据。

**人工要做的事**（两件）：
1. 浏览 `docs/自研手几何数据.md`，确认数值没有明显荒谬（如开口为负、端点角超 90°）。
2. 打开 `docs/hand_renders/` 下五档渲染图（每档 side/top 两张），与实机同电机位置的照片对比弯曲方向与形态——已验证：正角度 = 向掌面内侧卷曲（正确抓取方向）；拇指内旋几何为 θ=0°=外展（约垂直掌面）、θ=120°=贴掌，**电机方向（实机修正）：p=2000→贴掌、p=0→外展**。首次核验做一次即可，以后只在怀疑开度不准时重看。

**本次计算结果摘要**（2026-09-06，ID6 方向已实机修正）：四指贴掌端均为限位 90°（未触掌，名义贴掌，最近 21-23mm，贴掌端在 p=0）；拇指内旋贴掌端 120°（真实贴掌接触），**贴掌端在 p=2000**、p=0 为外展——`hand_bridge.py` 旧注释"2000=垂直掌心"方向写反，已修正（仅注释，动作库数值不受影响）。全开时拇尖-食尖 134mm、全闭 100mm。数值细节以 `docs/自研手几何数据.md` 为准。

## 阶段 2：清零旧补偿（约 10 分钟）

**目的**：`offset_xyz = [0.085, 0.01, -0.065]` 是旧手眼外参时代的 Inspire 补偿值，新基线下必须归零重测。

编辑 `config/grasp_config.json`：

```json
"offset_xyz": [0.0, 0.0, 0.0],
"offset_rpy_deg": [0.0, 0.0, 0.0],
"z_comp_knots": [[0.2, 0.0], [0.3, 0.0]],
"hand_mount_z": <阶段1工具输出的建议初值>
```

改完保存，重启终端A 生效。

> **注意（2026-09-06 已修复双源漂移）**：演示编排器 `anydex_eih_grasp.py` 的安装/补偿参数过去是文件内硬编码（与 config 各存一份，会漂移），现已改为统一读 `config/grasp_config.json`——**清零只需改 config 这一处**，标定/演示/预览三端同步生效。

**可选进阶（先跳过，需要时再做）**：如果想减少阶段 4-5 的迭代轮数、或精确锁定 `mount_yaw_deg`，可以做一次外置相机标定——手机/任意相机固定拍手背上的打印 ArUco 板，机械臂摆 5 个不同位姿（记录 getpose），解算"法兰→手"精确变换（把机械臂编码器当"相机"的手眼标定，精度 1-2mm）。此工具需要时找 ZCode 实现。

## 阶段 3：单点到位检查 + 偏差记录（约 2 小时，核心环节）

**目的**：隔离验证"抓取点→掌心"的定义：手臂到位后**停住不动**，看手指和物体的相对关系。所有没被 URDF 计算覆盖的真实误差（装配偏差、手眼残差、模型名义误差）在这一步现出原形。

**工具**：`anydex_eih_grasp_calib.py --calib-jog`（标定版编排器，带键盘微调和记录）。

### 3.1 启动

先 Ctrl+C 停掉终端A 的 `anydex_eih_grasp.py`（自动回零下电），改跑：

```bash
cd ~/Projects/AnyDexGrasp_ws/scripts
python anydex_eih_grasp_calib.py --calib-jog
```

### 3.2 每轮操作

1. 物体放桌面（前几轮固定位置，后几轮换位置换物体）。
2. 终端B `run_inspire_preview.py ...`（同阶段 0.3），Open3D 确认抓取框在物体上，回终端A 按回车。
3. 手臂自动运动到位、步进下降，按**空格/Esc** 可暂停接管。
4. **到位后停住**，从侧面拍照，回答三个问题：
   - 手指包络的空腔中心是否套住物体？（左右/前后偏多少 mm）
   - 沿接近轴方向手伸得太深/不够深？（约差多少 mm）
   - 拇指朝向是否合理（对着物体侧面）？——这一条核对 `mount_yaw_deg`，若系统性偏一个固定角，直接改 `config/grasp_config.json` 的 `mount_yaw_deg`（每次 ±5° 试）。
5. 键盘微调（基座系平移）：`w/s` 前后(X)、`a/d` 左右(Y)、`q/e` 上下(Z)、`r/f` 俯仰；步长 2/5/10mm。
6. 对准后按**空格**记录，自动写入 `logs/jog_calib_history.jsonl`。
7. Ctrl+C 回零结束本轮，换位置再来。

### 3.3 采样量

Type 3、Type 5 各 ≥5 次，物体分散在工作区近/远/左/右——都放一个点只能标出那一个点的偏差。

## 阶段 4：偏差分析与参数收敛（每轮 15 分钟，迭代 2-3 轮）

```bash
cd ~/Projects/AnyDexGrasp_ws/scripts/tools
python analyze_jog_history.py            # 默认读 logs/jog_calib_history.jsonl
```

| 分析输出 | 含义 | 改哪个字段 |
|---|---|---|
| 恒定偏置 mean(offset.xyz) | 整体偏固定量 | `offset_xyz` ← 原值 + 建议量 |
| 接近轴误差 mean(offset·approach) | 伸太深/不够深 | `hand_mount_z` ← 建议值 |
| 随深度变化的斜率显著 | 旋转标定残差 | offset 救不了，需查手眼外参（找 ZCode） |
| 朝向残余 mean(offset.rpy) | 手掌俯仰歪 | `offset_rpy_deg` ← 建议量 |

**迭代**：改配置 → 备份历史（`mv logs/jog_calib_history.jsonl logs/jog_calib_history_bak1.jsonl`）→ 重跑阶段 3 → 再分析。**收敛标准：平均偏差 < 5mm 且无固定方向**，通常 2-3 轮。

**电机映射的中段核验（一次性）**：若阶段 3 发现"位置准但预塑形开度明显不对"（手指张太开/太拢），说明线性映射中段有非线性。此时做一次简单核验：给电机发 1000，手机拍侧面照片，与阶段 1 工具加 `--render 1000` 参数导出的同档位渲染图对比，把偏差记入 `docs/自研手几何数据.md` 并在映射表中段加实测点。仅此一处可能需要"看照片"，不需要尺子。

## 判断速查表

| 现象 | 原因归类 | 处理 |
|---|---|---|
| 每次都偏同一个方向同样距离 | 系统性偏置 | 阶段 4 的 offset_xyz / hand_mount_z |
| 近处准、远处歪（或反过来） | 旋转残差 | 分析第 3 类结论，查手眼标定 |
| 渲染图里手就"握不住"物体 | 抓取候选/定义问题 | 检查 Open3D 抓取框，不是标定问题 |
| 位置准但开度不对、推倒物体 | 电机映射中段非线性 | 阶段 4 末尾的一次性照片核验 |
| 拇指朝向系统性偏一个角度 | mount_yaw 不准 | 改 `mount_yaw_deg`，±5° 逐步试 |
| 拇指扫到桌面 | 预塑形高度不够 | 编排器已有空中预塑形逻辑，检查执行时序 |
